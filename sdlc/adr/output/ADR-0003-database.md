## 1. 背景與問題（Context）

保費試算需查詢多維度費率表（商品／年齡／性別／年期），並保存計算紀錄供稽核。需選定主要資料庫。

- 業務驅動：費率資料關聯查詢複雜度高，計算紀錄需長期保存與查詢。
- 技術限制：需支援交易一致性與複雜索引。
- 前提假設：資料量在關聯式資料庫可承載範圍內。

---

## 2. 決策（Decision）

> **我們決定：採用 PostgreSQL 15。**

以 PostgreSQL 15 為主要資料庫，運用其 JSON 欄位、Partial Index 與成熟的關聯查詢能力支撐費率查詢與計算紀錄。

---

## 3. 考量的替代方案（Alternatives）

| 方案 | 優點 | 缺點 | 是否採用 |
|------|------|------|---------|
| **PostgreSQL 15** | JSON 欄位、Partial Index、關聯查詢強、開源成熟 | 需自行維運或用託管服務 | ✅ 採用 |
| MySQL 8 | 普及度高 | JSON 與部分索引能力較弱 | ❌ 否決：複雜查詢彈性不足 |
| MongoDB | 彈性 schema | 交易一致性與關聯查詢弱、費率關聯結構不適合 | ❌ 否決：資料本質為關聯式 |

---

## 4. 結果與影響（Consequences）

**正面：**
- 支援複雜費率查詢與 Partial Index 最佳化。
- 交易一致性保障計算紀錄正確。

**負面 / 取捨：**
- 需規劃備援與效能調校。

**後續行動：**
- 費率查詢熱點資料以 Redis 快取（見 ADR-0004）。
