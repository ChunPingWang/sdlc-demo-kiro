## 2. 樣式定義

### 2.1 段落樣式

| 樣式名稱 | 用途 | 字型 | 字級 | 粗體 | 顏色 | 段前間距 | 段後間距 |
|---------|------|------|------|------|------|---------|---------|
| `標題 1` | 章節標題（第 N 章） | 微軟正黑體 | 16 pt | ✓ | #1B3A6B（深藍） | 18 pt | 6 pt |
| `標題 2` | 小節標題（N.N） | 微軟正黑體 | 13 pt | ✓ | #2D6A9F（藍） | 12 pt | 4 pt |
| `標題 3` | 子節標題（N.N.N） | 微軟正黑體 | 11 pt | ✓ | #2D6A9F（藍） | 8 pt | 2 pt |
| `本文` | 一般內文 | 新細明體 / Calibri | 10 pt | — | #000000 | 0 pt | 6 pt |
| `表格內文` | 表格儲存格文字 | 新細明體 / Calibri | 9 pt | — | #000000 | 2 pt | 2 pt |
| `表格標頭` | 表格首列標題 | 微軟正黑體 | 9 pt | ✓ | #FFFFFF | 2 pt | 2 pt |
| `程式碼區塊` | 程式碼、指令、設定檔 | Courier New | 9 pt | — | #1E1E1E | 4 pt | 4 pt |
| `架構圖說明` | 圖表下方說明文字 | 新細明體 / Calibri | 9 pt | — | #595959（灰） | 2 pt | 6 pt |
| `ADR 決策` | 架構決策特殊標注 | 微軟正黑體 | 10 pt | ✓ | #7B3F00（棕橘） | 4 pt | 4 pt |
| `附註` | 備註說明 | 新細明體 / Calibri | 9 pt | — | #595959（灰） | 0 pt | 3 pt |

### 2.2 字元樣式

| 樣式名稱 | 用途 | 規格 |
|---------|------|------|
| `技術術語` | 技術名稱、框架、工具 | 粗體，顏色 #1B3A6B（深藍） |
| `API 路徑` | REST Endpoint 標注 | Courier New，背景 #EBF5FB |

| `警示` | 安全或效能警示 | 粗體，顏色 #C00000（紅） |
| `待確認` | 設計待定項目 | 斜體，顏色 #E67E22（橙） |

## 3. 頁首 / 頁尾設定

### 3.1 頁首（奇數頁）

```
左側：[公司 Logo]          中間：系統設計文件 - {PROJECT_NAME}          右側：文件編號 SD-XXXX
```

### 3.2 頁首（偶數頁）

```
左側：文件編號 SD-XXXX     中間：{章節標題}                              右側：[公司 Logo]
```

### 3.3 頁尾

```
左側：機密等級：機密（技術文件）    中間：第 X 頁，共 Y 頁    右側：© {YEAR} {COMPANY_NAME}
```

> SD 文件預設機密等級為「**機密**」，僅限技術開發相關人員閱覽。

## 4. 表格樣式

### 4.1 標準資料表格

- **標頭列：** 背景色 `#1B3A6B`，文字白色，字型微軟正黑體 9pt 粗體
- **奇數資料列：** 背景色 `#FFFFFF`（白）
- **偶數資料列：** 背景色 `#EBF5FB`（淺藍）
- **框線：** 外框 1pt 實線 `#1B3A6B`；內線 0.5pt 實線 `#AED6F1`
- **儲存格邊距：** 上下 0.1 cm，左右 0.2 cm

### 4.2 API 規格表

- 延伸自標準資料表格
- HTTP Method 欄位條件格式：
  - GET → 背景 `#D5F5E3`（淺綠）
  - POST → 背景 `#D6EAF8`（淺藍）
  - PUT / PATCH → 背景 `#FEF9E7`（淺黃）
  - DELETE → 背景 `#FDEDEC`（淺紅）

### 4.3 架構決策表（ADR）

- 標頭列背景 `#7B3F00`（棕橘），文字白色
- 資料列底色交替 `#FAE5D3` / `#FFFFFF`

## 5. 架構圖嵌入規範

### 5.1 圖表格式要求

| 項目 | 規格 |
|------|------|
| 匯出格式 | PNG（解析度 150 dpi 以上）或 SVG |
| 建議工具 | draw.io / Miro / PlantUML / C4 Model |
| 檔案命名 | `SD-{PROJECT_CODE}-arch-{序號}.png` |
| 存放位置 | `sdlc/sd/output/assets/` |

### 5.2 圖表說明格式

每張架構圖下方須加上說明段落，套用 `架構圖說明` 樣式：

```
圖 {章節}-{序號}：{圖表名稱}（{繪製工具}，{日期}）
```

範例：
```
圖 3-1：高階系統架構圖（draw.io，2025-01-15）
```

### 5.3 C4 Model 建議層次

| 層次 | 說明 | 套用章節 |
|------|------|---------|
| Level 1: System Context | 系統與外部角色關係 | 3.2 高階架構圖 |
| Level 2: Container | 主要容器/服務劃分 | 4.1 模組清單 |
| Level 3: Component | 模組內部元件設計 | 4.2 模組詳細設計 |
| Level 4: Code | 類別圖（選用） | 4.2 附錄 |

## 6. 程式碼區塊樣式

Word 中程式碼區塊建議使用以下設定：

- **樣式：** `程式碼區塊`（見 2.1 節）
- **框線：** 1pt 實線 `#CCCCCC`，左側 3pt 色塊 `#1B3A6B`
- **背景：** `#F8F9FA`（淺灰）
- **段落縮排：** 左縮排 0.5 cm

範例 Word 原始碼區塊外觀：

```
┌────────────────────────────────────────┐
│  pandoc SD-output.md \                 │
│    --reference-doc=SD-template.docx \  │
│    --output=SD-PROJ-v1.0.docx          │
└────────────────────────────────────────┘
```

## 7. 從 Markdown 轉換為 Word 的作業步驟

### 方式一：Pandoc 指令（推薦）

```bash
pandoc SD-output.md \
  --reference-doc=SD-template.docx \
  --toc \
  --toc-depth=3 \
  --output=SD-{PROJECT_CODE}-{VERSION}.docx
```

> **前置需求：** 安裝 [Pandoc](https://pandoc.org/) 與參考套版 `SD-template.docx`。  
> 套版檔案須預先設定好第 2 節所定義的所有樣式。

### 方式二：手動套版

1. 以 Word 開啟 `SD-template.docx`
2. 另存新檔為 `SD-{PROJECT_CODE}-{VERSION}.docx`
3. 依章節複製 Markdown 內容，使用「保留來源格式貼上」
4. 架構圖以「**插入 > 圖片**」方式嵌入，套用 `架構圖說明` 樣式
5. 程式碼片段套用 `程式碼區塊` 樣式
6. 更新目錄：**右鍵 > 更新欄位 > 更新整個目錄**
7. 確認頁首頁尾資訊正確
8. 確認「待確認」事項已全部處理或轉為 Issue 追蹤

## 8. 輸出命名規則

```
SD-{PROJECT_CODE}-v{MAJOR}.{MINOR}.docx

範例：
  SD-ECOM-v1.0.docx    （初版設計）
  SD-ECOM-v1.3.docx    （第三次設計修訂）
  SD-ECOM-v2.0.docx    （重大架構改版）
```

輸出檔案存放於：`sdlc/sd/output/`  
架構圖等附件資產存放於：`sdlc/sd/output/assets/`

## 9. 版本控制規則

| 版本類型 | 版號變更 | 觸發條件 |
|---------|---------|---------|
| 重大架構改版 | v**X**.0 → v**X+1**.0 | 架構模式變更、主要技術棧替換 |
| 設計修訂 | vX.**Y** → vX.**Y+1** | 模組調整、API 新增/修改、資料模型變更 |
| 文字校正 | vX.Y（標注 patch）| 錯字、格式修正，不影響設計內容 |

## 10. FSD 與 SD 的版本對應關係

| FSD 版本 | SD 版本 | 說明 |
|---------|---------|------|
| FSD-{CODE}-v1.0 | SD-{CODE}-v1.0 | 初版對應 |
| FSD-{CODE}-v1.x | SD-{CODE}-v1.x | 同步修訂 |
| FSD-{CODE}-v2.0 | SD-{CODE}-v2.0 | 重大改版同步升版 |

> 當 FSD 發生重大修訂時，SD 須評估影響範圍並同步更新，並在修訂紀錄中標注對應的 FSD 版本號。
